# 사케 노트 · 스시·사케 기록 (데모)

스시·오마카세 업장 방문 기록과 사케 노트를 한 화면에서 관리하는 모바일 웹앱의 **데모 빌드**입니다.

- 웹 주소: https://circlekim87-ctrl.github.io/sake-sushi-log/
- 단일 `index.html` 파일 (외부 라이브러리·폰트·CDN 요청 없음)
- 업장명·주소·좌표·사진·메모는 **전부 예시 데이터**이며, 실제 방문 정보나 사진은 포함되어 있지 않습니다.

## 탭 구성

1. **업장별** — 방문 타임라인, 그날 마신 사케 태그, 사진 모아보기
2. **사케 목록** — 마신 사케 목록, 검색·등급 필터, 시음 메모
3. **+ 기록** — 사진 업로드 → EXIF 촬영 일시·GPS 추출 → 업장 묶음(주변 업장 추천), 사케 라벨 연결
4. **격자** — 사진 4장을 원본 비율 유지 2×2 정사각형으로 합성

데이터는 브라우저 `localStorage`(`sakeSushiLog.demo.v1`)에만 저장되며 서버로 전송되지 않습니다.

## 위치 기반 업장 추론

사진 EXIF의 GPS로 업장을 찾습니다. 이미 가 본 업장이 설정한 반경(기본 5m) 안에 있으면 자동 선택하고,
처음 가는 곳이면 같은 반경의 업장 후보를 `+ 기록` 화면에 칩으로 보여 줍니다(누르면 업장명·지역·주소 자동 채움).

- 기본 조회 반경은 **5m** — 사진을 찍은 바로 그 자리만 후보가 됩니다.
- 실내 GPS 오차로 0건이면 `반경 5m 내에 등록된 업장이 없어요.` 안내와 **[30m로 넓혀 찾기]** 버튼이 뜹니다(30 → 100 → 200m).
- 설정 › 위치 · 업장 추론 › **기본 조회 반경**에서 `5m`(기본) / `20m` / `50m` / `100m` 로 바꿀 수 있습니다.
- 설정에 카카오 로컬 REST API 키를 넣으면 카카오 로컬(음식점 `FD6`, 같은 반경)로 먼저 조회합니다.
- 키가 없거나 실패하면 OpenStreetMap Overpass API 로 조회하고, 막힌 네트워크에서는 같은 OSM 데이터를
  Nominatim 역지오코딩·카테고리 검색(`q=[amenity=restaurant]`, 같은 반경)으로 받아 옵니다.
- 외부로 나가는 값은 사진의 좌표뿐입니다. 조회가 실패하면 안내만 표시하고 수동 입력은 그대로 쓸 수 있습니다.
- 조회는 어떤 상황에서도 끝납니다 — 개별 요청 4초 · 한 번의 조회 전체 6.5초 · 안전망 8초.
  네트워크가 느리거나 막혀도 '찾는 중'에 머무르지 않고 `주변 업장을 조회하지 못했어요` + **[다시 찾기]** 로 넘어갑니다.
- 업장이 이미 정해진 기록에서도 `③ 업장` 카드의 **[이 위치 주변 업장 다시 찾기]** 버튼으로 추천 영역을 언제든 다시 열 수 있고,
  **[접기]** 로 다시 접을 수 있습니다.
- 사진을 더하거나 빼면 GPS 중앙값이 새로 잡히고, 앞서 잡아 둔 업장이 그 위치에서 멀어졌으면 연결을 풉니다
  (자동으로 채운 이름·지역·주소는 함께 비우고, 직접 입력한 이름은 남깁니다). 새 위치의 후보를 바로 다시 찾습니다.
  사진을 모두 지우면 사진에서 나온 위치·자동 업장도 함께 비워집니다.
- '샘플로 체험'한 기록에 내 사진을 고르면 샘플 사진·사케 초안을 먼저 비우고 새 사진 좌표로 판단합니다.
- 역지오코딩으로 동네명을 얻으면 `② 촬영 정보` 의 위치 줄에 `위치 37.52000, 127.05000 · 서울 강남구 역삼동` 처럼 함께 보여 줍니다.
- 지도 데이터 © OpenStreetMap contributors

## 화면

- iOS Safari 에서 `input[type=date]` · `input[type=time]` 이 카드 오른쪽 경계를 넘어가지 않도록
  폭을 고정했습니다(`min-width:0; width:100%; max-width:100%`).

## 기술

- 순수 HTML/CSS/JS 단일 파일, 프로토타입 단계
- 지도 조회 외에는 외부 요청이 없습니다.
